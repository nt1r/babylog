# Test Plan

## Unit Tests

| Requirement / Scenario | Verification | Expected Result |
| --- | --- | --- |
| `baby-profile` / `Baby profile update` / `Preserve or update default_clinic_name on baby profile update` | 在 `backend/internal/baby/baby_test.go` 测试 `ValidateAndNormalize` 对合法裁剪、空串与超长（>80 字）`default_clinic_name` 的校验；在 `backend/internal/baby/store_test.go` 测试 `Store.Create`、`Store.Update` 与 `Store.UpdateDefaultClinic`：（1）新建未传时默认为 `""`；（2）更新传入含首尾空格的合法名称后回读 SQLite；（3）再次更新省略（`nil`）回读 SQLite；（4）传入空串 `""` 回读 SQLite；（5）传入超长名称 | （1）落库 `""`；（2）落库裁剪后的门诊名称；（3）省略时保留既有默认门诊不被清空；（4）空串清空为 `""`；（5）返回 `*ValidationError` 且不修改数据库 |
| `vaccine-management` / `Dose status transitions and record updates` / `Auto-remember first non-birth clinic and respect explicit default clinic pin` | 在 `backend/internal/vaccines/store_test.go` 使用固定时钟对空 `default_clinic_name` 的宝宝依次执行：（1）完成产院 `hepb` 第 1 剂并填 `"市妇幼保健院"`；（2）预约或完成 1 月龄 `hepb` 第 2 剂并填 `"阳光街道社区卫生服务中心"`；（3）预约另一剂填 `"儿童医院"` 且 `SetDefaultClinic: false`；（4）预约另一剂填 `"高新社区卫生服务中心"` 且 `SetDefaultClinic: true`；每步回读 `baby_profiles` | （1）产院记录不污染默认门诊，`default_clinic_name` 保持 `""`；（2）首次常规门诊自动写入 `"阳光街道社区卫生服务中心"`；（3）偶发医院不覆盖既有默认门诊；（4）显式 `SetDefaultClinic: true` 更新为 `"高新社区卫生服务中心"` |
| `vaccine-management` / `Batch appointment booking and historical completion` / `Batch update rolls back default clinic change on invalid dose ID` | 在 `backend/internal/vaccines/store_test.go` 对空默认门诊宝宝测试合法常规剂次 `BatchUpdate` 自动记住默认门诊；再对批量接口传入合法 `clinic_name`、`SetDefaultClinic: true` 与包含不存在剂次 ID 的列表并回读目标剂次与 `baby_profiles` | 合法常规剂次批量写入时 `default_clinic_name` 原子落库；含非法 ID 时返回 `ErrNotFound` 且事务完整回滚（合法剂次与 `default_clinic_name` 均未改动） |
| `daily-records` / `Smart defaults endpoint for low-friction entry` / `Compute smart defaults from recent history` & `Return sensible starter defaults when history is empty` | 在 `backend/internal/records/store_test.go` 扩展 `TestGetSmartDefaultsHeuristics`：（1）空历史断言 `last_milk_subtype == "formula"`、`last_breast_mode == "direct"`、`last_breast_duration_min == 15`、`recent_solids` 为空、`sleep.suggested_nap_min == 60`、`sleep.suggested_night_min == 480`；（2）写入配方奶、亲喂、瓶喂母乳与最新辅食（带 `solid_amount`）以及多条 `nap`（40/45/50/120/45 分钟）与 `night`（540/600/570 分钟）记录后调用 `GetSmartDefaults` | `last_feeding_subtype` 为 `"solid"` 但 `last_milk_subtype` 保持 `"breast"`、`last_breast_mode` 匹配最近母乳方式、`last_breast_duration_min` 为 12、`recent_solids` 去重保留前 5 项且携带对应最近份量、`sleep.suggested_nap_min` 为 45、`sleep.suggested_night_min` 为 570 |

## Integration Tests

| Requirement / Scenario | Verification | Expected Result |
| --- | --- | --- |
| `baby-profile` / `Baby profile retrieval and onboarding status` & `Baby profile update` / `Preserve or update default_clinic_name on baby profile update` | 在 `backend/internal/httpapi/records_dashboard_test.go` 的 `TestBabyProfileLifecycleAndAuthGuards` 中经 HTTP 验证 `GET /api/baby` 返回 `default_clinic_name`，`PUT /api/baby` 传入合法值、省略字段、传入空串与超长（>80 字符）值的状态码与落库终态 | 合法值返回 HTTP 200 并持久化，省略字段保留旧值，空串清空，超长返回 HTTP 400 中文错误 JSON |
| `vaccine-management` / `Explicit default vaccination clinic management` / `Set and clear default vaccination clinic` & `Reject oversized default clinic name` | 在 `backend/internal/httpapi/vaccines_test.go` 经 HTTP 调用 `PUT /api/vaccines/default-clinic` 设置、读取 `GET /api/vaccines` 验证 `default_clinic_name`、清空及传入超长名称，并验证 `PUT /api/vaccines/:id` 自动记住首次常规门诊与显式 `set_default_clinic: true` | 设置/清空返回 HTTP 200 且与 `GET /api/vaccines`、`GET /api/baby` 一致；超长返回 HTTP 400 中文错误 JSON；首次常规剂次自动记住且显式置顶可更新 |
| `daily-records` / `Smart defaults endpoint for low-friction entry` / `Compute smart defaults from recent history` | 在 `backend/internal/httpapi/records_dashboard_test.go` 经 HTTP 创建母乳、带份量辅食与小睡/夜觉记录后请求 `GET /api/records/defaults` | 返回 HTTP 200，JSON 包含 `feeding.last_milk_subtype`、`feeding.last_breast_mode`、`feeding.last_breast_duration_min`、`feeding.recent_solids` 与 `sleep.suggested_nap_min`、`sleep.suggested_night_min` 且数值与写入记录一致 |
