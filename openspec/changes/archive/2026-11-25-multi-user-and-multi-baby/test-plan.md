# Test Plan

遵循 [AGENTS.md](../../../AGENTS.md) 与 [docs/testing-guide.md](../../../docs/testing-guide.md)：后端自动化测试按 Testing Trophy 分层编写（纯单元、极少量底层持久化不变量、黑盒 HTTP API 全链路集成测试、真实二进制 CLI 测试），不引入第三方测试依赖，前端不维护常驻自动化测试。

## Unit Tests

| Requirement / Scenario | Verification | Expected Result |
| --- | --- | --- |
| `admin-auth` / `Login brute-force throttling and scrypt concurrency guard` / `Throttle repeated failed login attempts for a username` | 在 `backend/internal/auth/limiter_test.go` 使用注入时钟测试 `LoginGuard`：对同一归一化用户名（混用大小写）连续记录 10 次失败、第 11 次检查拒绝、推进时钟越过 15 分钟窗口后自动恢复、登录成功清零计数，以及超过全局并发上限（8）时快速拒绝 | 第 11 次在窗口内返回限流错误；越过 15 分钟窗口或登录成功后重新放行；并发槽满时立即返回限流错误且不阻塞死锁 |
| `admin-auth` / `Administrator login and session creation` / `Enforce Secure cookie flag when BABYLOG_COOKIE_SECURE is enabled` | 在 `backend/internal/config/config_test.go` 表驱动测试 `BABYLOG_COOKIE_SECURE` 未设置、`true`/`false` 及非法值解析 | 未设置默认为 `false`；`true`/`false` 准确解析；非法字符串返回明确中文配置错误 |
| `user-management` / `Single-administrator lifecycle invariant` / `Prevent creating a second administrator` & 存量 v4→v5 迁移不变量 | 在 `backend/internal/database/database_test.go`（或 `backend/internal/auth/store_test.go`）构造执行至 `00004` 的旧版 SQLite（含 `administrator(id=1)`、有效 `sessions`、`baby_profiles` 及 5 张子表数据）再运行 `database.Open` 升级至 `00005`，并验证向 `users` 插入第二个 `role='admin'` 行及对空库执行 `00005` 迁移 | v4 数据零丢失迁移为 `users(id=1, role='admin')`、`sessions.user_id=1`、`baby_profiles.user_id=1` 且 `PRAGMA foreign_key_check` 为空；空库迁移成功；插入第二个 `role='admin'` 被部分唯一索引拒绝 |

## Integration Tests

| Requirement / Scenario | Verification | Expected Result |
| --- | --- | --- |
| `admin-auth` / `Administrator login and session creation` & `Login brute-force throttling and scrypt concurrency guard` / `Successful administrator login`, `Reject invalid credentials`, `Reject disabled user after password verification succeeds`, `Throttle repeated failed login attempts for a username`, `Enforce Secure cookie flag when BABYLOG_COOKIE_SECURE is enabled` | 在 `backend/internal/integration/auth_test.go` 扩展认证集成用例：创建大小写混合用户名用户、以小写登录校验返回 `{ id, username, role, must_change_password }`、验证停用用户输错密码返 401 而输对密码返 403、连续 10 次失败后第 11 次返 429 并用 `FakeClock` 推进 15 分钟后恢复、启用 `CookieSecure` 校验 `Set-Cookie` 含 `Secure` | 各场景状态码（200 / 401 / 403 / 429）、中文报错、Cookie 属性及会话落库状态全部符合规格 |
| `admin-auth` / `Session restoration and expiration` / `Clear expired or unknown session cookie` & `Administrator logout` / `Revoke session on logout` | 在 `backend/internal/integration/auth_test.go` 同时登录 User A 与 User B：A 登出验证 B 会话不受影响；管理员停用 B 后，B 调用 `GET /api/auth/session` 与受保护接口并回读 `sessions` 表 | A 登出仅删 A 的 token 且 B 仍返回 200；B 被停用后立即返回 `{ user: null }` + 清 Cookie 及受保护接口 401 |
| `admin-auth` / `Self-service password change` & `Mandatory password change gate` / 全量场景 | 在 `backend/internal/integration/auth_test.go` 新增 `TestAuthForcedAndSelfServicePasswordChangeClosedLoop`：登录 `must_change_password: true` 用户（同时在两客户端持有会话），先尝试访问 `/api/babies`、`/api/admin/users` 验证 403 `PASSWORD_CHANGE_REQUIRED`，再提交错误旧密码 401、相同新旧密码 400、合法新密码 200 | 改密成功清除 `must_change_password`、轮换当前会话、立即吊销另一客户端会话（401），随后可正常访问 `/api/babies` |
| `user-management` / `Admin web user management API` / 全量场景 | 在 `backend/internal/integration/user_management_test.go` 新增管理员与普通用户闭环用例：验证普通用户访问 `/api/admin/users*` 统一 403；管理员创建用户（201、`must_change_password: true`、忽略重复大小写 409）、列出用户（不含宝宝/记录数）、重置普通用户密码（吊销旧会话 + 置 `must_change_password: true`）、停用/启用普通用户，以及尝试停用或重置管理员自身返回 400 | 所有权限边界、冲突拒绝、自身保护与会话吊销落库终态准确无误 |
| `baby-profile` / `Multi-baby profile creation`, `Baby profile retrieval and onboarding status`, `Baby profile update`, `Hard deletion of a baby profile` / 全量场景 | 在 `backend/internal/integration/baby_profile_test.go` 迁移并新增多宝宝与跨用户用例：User A 创建 2 个同名/异名宝宝与 User B 互不可见；User A 建满 10 个后第 11 个返回 400 而 User B 仍可建档；User B 尝试 `PUT`/`DELETE` User A 的 `babyId` 返回 404 且 A 数据不变；User A 硬删除含全量 5 类子表记录的宝宝后只读核验 SQLite 5 张子表均已级联清零且额度释放 | 列表隔离、10 宝宝上限、跨用户 404 防越权、硬删除 `ON DELETE CASCADE` 落库终态全部验证通过 |
| `daily-records` / 全量 `MODIFIED` 路由与跨用户/跨宝宝隔离场景 | 迁移 `backend/internal/integration/daily_records_test.go` 至 `/api/babies/:babyId/records/*`，并新增 `TestRecordsCrossUserAndCrossBabyIsolation`：User A 拥有大宝/二宝、User B 拥有三宝，交叉验证列表、智能默认值、跨宝宝 `PUT`/`DELETE` `record_id` 与跨用户 `babyId` 访问 | 跨用户 `babyId` 与跨宝宝 `record_id` 全部返回 404 且目标记录原样保留，智能默认值与列表统计零串扰 |
| `dashboard-insights` / 全量 `MODIFIED` 路由与跨用户/跨宝宝隔离场景 | 迁移 `backend/internal/integration/dashboard_insights_test.go` 至 `/api/babies/:babyId/dashboard/*`，验证多宝宝下 `summary`/`trends` 严格按 `:babyId` 聚合且跨用户/不存在 `babyId` 返回 404 | 看板 KPI、趋势与节律仅反映目标宝宝，跨用户请求返回 404 不泄漏数据 |
| `vaccine-management` / 全量 `MODIFIED` 路由与跨用户/跨宝宝隔离场景 | 迁移 `backend/internal/integration/vaccine_management_test.go` 至 `/api/babies/:babyId/vaccines/*`，并新增跨用户/跨宝宝越权用例：包含以他人 `babyId` 访问 404、单剂 `PUT`/`DELETE` 传兄弟宝宝或他人 `dose_id` 返回 404、`POST /batch` 混入兄弟/他人 `dose_id` 整事务回滚 404、不同宝宝独立导入 `pcv13` 互不冲突 | 疫苗计划初始化、模板导入、单剂与批量原子回滚、默认门诊同步在多宝宝与多用户下均严格隔离 |
