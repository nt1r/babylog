# 多用户采用单库行级两级归属、显式 `:babyId` 后端路由与管理员隐私隔离

BabyLog 在保留单 SQLite 文件与零 CGO 部署形态的前提下引入多用户与单用户多宝宝能力，刻意放弃每用户独立 SQLite 文件（运维、迁移与连接池复杂度高）及独立家庭/成员工作区表（当前一户一账号场景下属于过度设计），改为由 `users -> baby_profiles -> 业务表` 两级外键实现行级逻辑隔离：5 张记录与疫苗表不冗余 `user_id`，而是统一通过入口中间件以当前登录 `user_id` 校验目标 `:babyId` 归属后向下透传。后端业务接口显式采用 `/api/babies/:babyId/...`（避免同账号多设备并发操作不同宝宝时串扰），而前端浏览器保持无 ID 简洁路径并按 `userId` 隔离本地记忆当前宝宝（避免大面积重构前端导航路由）。同时，系统通过数据库部分唯一索引强制全局仅存在单一 `admin`，该管理员仅拥有账号生命周期管理权（创建、重置密码、启停用），不提供任何跨账号查看或修改他人宝宝与记录数据的接口，确保运维权限与家庭隐私数据严格分离。
